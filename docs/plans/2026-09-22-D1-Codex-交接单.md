# D1 交接单：KB-AI 契约变更（致 `codex-picturebook-agent` 维护者）

> 出单方：`picturebook-screenwriter`（WorkBuddy 插件，绘本编剧工坊）
> 收单方：`codex-picturebook-agent`（GitHub，同一飞书 KB 契约的原生移植版）
> 日期：2026-09-22
> 来源：本包 9 笔提交 `8e94873..b4aa89e`（分支 `feat/d1-ai-overwrite`），产品决定编号 **D1**
> 本文自包含——读者无需访问出单方仓库。**出单方不代改对侧仓库。**

---

## 零、一句话

飞书 **KB-AI 页面**的内容权威已从「人类编辑优先」翻转为「**AI 合成为内容权威**」：人工对 KB-AI 页面的直接编辑不再有粘性，下一次同步即被 AI 合成覆盖；随之，三方合并与冲突队列机制整体退役。两侧共享同一 KB 契约，**对侧须镜像本轮三处契约变更**，否则两运行时不一致。

---

## 一、变更了什么，为什么

产品决定：放弃「人类编辑优先」不变量。此前人工直接改 KB-AI 页面后，同步会走三方合并、必要时把冲突入队等人工裁决；现在改为——**AI 合成结果即页面内容权威**，人工直接编辑不再保留（人工新增、人工删除都同样被覆盖），三方合并与冲突队列（含 `conflict-resolve`）整体退役，改为在同步报告里**披露**本轮被覆盖的人工编辑页，使丢失可见。原因：三方合并与人工优先语义在协议层与「源未变时用合成结果替换存量页」直接冲突，且冲突队列长期恒空、机制成本高于收益。

> 明写的后果：人工在 KB-AI 上的精修会在下次同步**无声丢失**——这正是第 3 节「行为警告」存在的理由。

---

## 二、三处 wire / 契约变更（逐条 before → after）

### 变更 1：覆盖语义（页级判定）

| | before | after |
|---|---|---|
| 判定输入 | 读**源版本向量**：`source_changed = candidate.source_revisions != entry.source_revisions`；源未变即 `preserve` 短路 | **不读源版本向量** |
| 历史基线 | 源变化时读**历史版本基线**（`last_ai_revision_id`）并解析，做三方合并 | **不读历史基线**（取基线的方法已删） |
| 判定核心 | 三方比较（当前页 / 历史基线 / 候选）产出 `publish` / `preserve` / `queue` / `needs_review` | 只比较**候选与当前页的规范化渲染**（`render_remote_page`，元数据取当前页页尾元数据）：**不同 ⇒ 发布（覆盖）**，**相同 ⇒ 保留（不写）** |
| 判决取值 | `publish` \| `preserve` \| `queue` \| `needs_review` | `publish` \| `preserve` \| `needs_review`（`queue` 消失） |
| 入队 | 语义冲突 / 历史版本不可读 ⇒ `queue`（向冲突队列追加一行） | **不入队**（队列机制退役） |
| `merge_protocol` | `classify` / `plan_merge` / `merge_preserving_human` / `validate_decision` | **整模块删除**（文件已移除） |
| 配置 | `settings.json` 的 `humanEditWins: true` | `humanEditWins: false` |

判定退化的实质：**「候选与当前页规范化渲染是否相同」**——不同即发布（覆盖），相同即保留（零触碰、不推进 page revision）。配套删除的符号：读历史基线的方法、向队列追加的方法（`_queue`）、`ACTION_QUEUED` 常量、三方合并的 import 与依赖。原「源未变时仍可替换存量页」的设计空缺（旧编号 D1）因此自然闭合——不再需要任何 force 开关。

### 变更 2：同步报告 schema（JSON 报告 + 同步日志行）

| 项 | before | after |
|---|---|---|
| 报告键 `conflicts` | 本轮入队的逻辑键列表 | **删除** |
| 报告键 `third_party_edits` | 源未变而未被触及、页面 revision 前进的页（逐页整页 fetch 检出） | **删除**（连同 `_audit_third_party` 一并删除） |
| 报告键 `overwritten_human_edits` | 不存在 | **新增**：逻辑键列表，`sorted(set(...))` 升序去重 |
| `counts` 键 | `{published, preserved, queued, failed, retried}` | `{published, preserved, failed, retried}`（**去掉 `queued`**） |
| 同步日志行计数 | 「发布 / 保留 / **入队** / 失败 / 重试」 | 「发布 / 保留 / 失败 / 重试」 |

**`overwritten_human_edits` 的记录时机是本变更的关键约束**：只在条件更新**确实写成之后**才 append——判定条件是「当前页 revision 相对索引 `last_seen_revision_id` 前进」（即上一次同步后页面被人工/对侧改过），且放在**成功路径**上。保留（内容规范化后相同、页面零触碰）与 `needs_review`（partial / warnings、竞态重试耗尽——本轮未发布、页面未动）**都不入列**。否则会出现「没覆盖却报告覆盖」的误报。

> 补充：**dry-run 报告**同样去掉 `conflicts` 与 `counts.queued`；dry-run **不产出** `overwritten_human_edits`（该键只在真实报告里，dry-run 无此字段）。

### 变更 3：控制面（ControlPlane）

| | before | after |
|---|---|---|
| `control_tokens` 合法键 | `{index, lock, conflict_queue, admission}` | `{index, lock, admission}`（**去掉 `conflict_queue`**） |
| `read_conflict_queue()` / `append_conflict()` | 存在 | **删除** |
| 远端页 `AI_KB_CONFLICT_QUEUE_V1` | 解析并读写 | **保留原位、孤儿化**——**不删远端节点**，只是不再解析、不再写入（解析器与 token 定位已删） |
| wiki-lint 协议检查 | **五检**（含 `conflict_queue_format`） | **四检**（`conflict_queue_format` 退役）；剩余：索引与树一致性 / 页尾元数据 schema / 重复逻辑键 / 索引键作用域 |
| lint fixture | 导出 `index.md` + `conflicts.md` + `tree.json` + `pages/` | **不再导出 `conflicts.md`** |
| `store_cli` 子命令 | 含 `conflicts`（只读）/ `conflict-resolve`（写） | 两条子命令**删除** |
| steward 操作集 | **15 项**（含「冲突队列查看」「冲突处理」） | **13 项**（退役两项；其余操作号顺延） |

**注意「孤儿化」不等于「删除」**：远端 `AI_KB_CONFLICT_QUEUE_V1` 节点（99_系统控制台直系子节点）**保留原位不动**。对侧镜像时也**不要**去删这个远端节点，只是把代码里对它的解析/读写入口摘掉。

## 三、行为警告（对侧不可漏）

1. **`needs_review` 的语义已变**。它现在的含义是「**资源/评论块 / partial update / revision 竞态重试耗尽**」，**不再与冲突队列有任何关系**。特别地：条件更新遇到 revision 冲突、重试次数耗尽时，现在**标 `needs_review` 并把 `counts.failed` 加一**（不再是 `queued`），按「本轮不发布、下轮自然重试」处理。任何「`needs_review` ⇒ 去读冲突队列 / 提示人工裁决」的旧代码路径都必须改掉。
   - 附带：索引里出现 `needs_review` 条目会让 wiki-lint 出 **WARN**，该状态**能自愈**（下一轮该页仍是候选、发布成功后 status 回 `published`）。

2. **人工编辑被覆盖是静默的**——这是本决定的最大运维风险。唯一可见性来自同步报告的 **`overwritten_human_edits`** 字段。**故对侧必须实现该字段**（含「只在写成后记录、保留与 needs_review 不入列」的时机约束），否则「人工精修消失」这件事将**不可见**，「丢失不可见」正是 D1 想用披露兜住的唯一防线。实现该字段前，对侧的覆盖是**无披露的静默覆盖**，比出单方更危险。

3. 连带的措辞：steward 回传格式里「冲突入队: {n} 条」已改为「**覆盖人工编辑: {n} 页**」；「冲突与待处理」段落的样例改为引用 `overwritten_human_edits`。

## 四、明确不在本次范围内

- **出单方不代改对侧仓库。** `codex-picturebook-agent` **不在**出单方仓库或任何工作树内，也未定位、未克隆。本单只是变更通知与镜像清单，**需用户在对侧仓库另起一笔**来实施。
- **对侧未镜像前，两运行时契约不一致。** 具体不一致点：一侧按新契约为 `control_tokens` 只提供 `{index, lock, admission}`、报告含 `overwritten_human_edits`；另一侧若仍按旧契约**要求 `conflict_queue` 键**（`ControlPlane` 构造会因缺键或多余键报错）、或**去读 `conflicts` / `third_party_edits` 报告字段**，则任一侧的同步/读取都会失败或误读。
- **因此：跨侧读写同一 KB 之前，须先完成对侧镜像。** 在完成前，不要让两个运行时并发操作同一 KB-AI。
- 本文只覆盖「契约同步」本身；对侧的测试重写、文档口径改写等随其实施一并完成，不在本单逐项展开。

## 五、对侧镜像清单（供实施时对照）

按变更分组，对侧需自查这些落点（名称以对侧实际为准，语义必须一致）：

- **覆盖语义层**
  - 页级判定：去掉「源版本向量比较 + 源未变即保留短路」；改为「候选与当前页**标记不敏感形态**相同 ⇒ 保留 / 不同 ⇒ 发布覆盖」。**〔2026-09-23 更正，重要〕** 本行原写「**规范化渲染**相同」——**照字面实现会得到坏版本**：飞书 docx 往返会对标记做规范化（首行空行被吞、块引用行尾加双空格、表格多出空单元格、URL 自动链接化、`_`/`*` 被转义、相邻粗体段合并），故「渲染后比较」**恒不相等** ⇒ 每轮重写全部页面。正解是两侧都过对称的**去标记**（出单方实现为 `remote_markdown.mark_insensitive`：自动链接拆包、去转义、去全部 `*`/`_`、表格去空尾格、去行尾空白与空行；**仅用于比较、不用于写**）。详见 `2026-09-23-第二批-Codex-交接单.md` 第 1 项。
  - 删除三方合并模块（`classify` / `plan_merge` / `merge_preserving_human` / `validate_decision`）及其测试。
  - 删除读历史版本基线、向队列追加、第三方写入整页审计等方法。
  - 配置文件 `humanEditWins` 改 `false`（或等价字段）。
- **报告层**
  - 报告键：删 `conflicts`、删 `third_party_edits`；增 `overwritten_human_edits`（`sorted(set())` 去重、只在写成后记录）。
  - `counts`：删 `queued`；同步日志行去掉「入队」。
  - dry-run 报告同步去 `conflicts` / `counts.queued`。
- **控制面层**
  - `control_tokens` 合法键：`{index, lock, admission}`。
  - 删 `read_conflict_queue` / `append_conflict`。
  - 远端 `AI_KB_CONFLICT_QUEUE_V1`：保留原位、不再解析（**不删远端节点**）。
  - wiki-lint：五检降四检，退役 `conflict_queue_format`；fixture 不再导出 `conflicts.md`。
  - CLI：删 `conflicts` / `conflict-resolve` 两条子命令；操作集 15→13。
- **行为层**
  - `needs_review` 语义改写（资源/评论块 / partial / 竞态耗尽），与冲突队列解耦；竞态耗尽 ⇒ `needs_review` + `failed` 计数 + 下轮自然重试。
  - 实现 `overwritten_human_edits` 披露（否则静默覆盖无可见性）。
