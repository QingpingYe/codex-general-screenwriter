## 三、两处结构性发现（请贵方裁定）

### 3.1 `archived` 在现有实现下不可得——贵方 §4.2 的处方落不了地

`archived` 在我方代码里**只有读侧语义，没有任何写侧**：`models` 声明它、`consumer.select` 过滤它、
`control_plane` 校验它，而**没有任何代码写它**；`store_cli` 的十二个子命令里也没有归档/移除索引
条目的入口。

更关键的是：即使把 `status` 改成 `archived`，**也修不好**。`export_lint_fixture` 逐条遍历索引、
对**每一条**都 fetch `entry.doc_token`，**不按 status 过滤**（`read_index` 同样不过滤）：

```python
for entry in self.entries().values():
    _revision, content = fetch_document(self.cli, entry.doc_token, kind="page")
```

于是「保留条目、标 archived」会留下一条指向已删文档的墓碑 → fetch 报 `3380003` → **整个 lint 导出
硬停**，正是我方当时实测到的现象。所以贵方 §4.2 的三条要求（条目留档、物理页不删、审计字段保留）
在当前实现下是**三条同时成立不了的**：

- 页面若不删，条目留档可行（普通归档）；
- 页面若已删，条目必须**移除**，否则 lint 永远跑不动。

我方选择移除。**请贵方裁定协议要哪一种**，并据以补：

1. 若要**墓碑**：两侧都需让 `export_lint_fixture` 跳过 `archived` 条目（并明确「归档页允许其文档
   已不存在」这一不变量），且需有一个**写侧入口**把条目置为 `archived`。
2. 若要**移除**：需在协议里写明「移除索引条目」的合法流程与前置校验（例如「来源必须另有活动页」
   或显式确认孤儿），同样需要一个受管入口。

无论哪种，都请把该操作补进协议「写入与同步流程」节——目前它只在贵方那封信里以一句话出现，
协议正文没有对应条款。

### 3.2 人工编辑控制面文档会被飞书重写围栏大小写——`_parse_control` 曾因此硬停全管线

这是本次执行中真实撞到、并已修掉的一处**代码脆弱性**，贵方可能有同源代码，故一并报。

**现象**：按 §1.2 手工改完索引后，`lint-fixture` 报

```
索引/控制面异常，已停止写入：control document format is invalid
```

**根因**：`_parse_control` 原先要求**逐字节**匹配开场围栏：

```python
prefix = heading + "\n```json\n"          # 大小写敏感、无容忍
if not content.startswith(prefix) or ...: raise ControlPlaneCorrupt(...)
```

而控制面文档是**人可编辑的 wiki 文档**。手工粘贴进代码块后，飞书 docx 往返按代码块的「语言」属性
重写围栏，导出成了 ```JSON（大写）。于是 `startswith` 失败 → 控制面被判损坏 → **索引读不出 →
整条管线（含 lint 导出）不可用**。人类肉眼完全看不出问题：内容一字不差，只有一个字母的大小写。

**修法**（只放宽大小写，其余不放松）：

```python
opener = re.compile(r"\A" + re.escape(heading) + r"\n```(?i:json)\n")
```

`(?i:json)` 只作用于语言标记；**heading 仍大小写敏感、围栏内 JSON 仍严格解析**，schema 校验一条
不减。配套 4 条测试：1 条驱动（`json`/`JSON`/`Json`/`jSoN` 四种都须解析成功）+ 3 条守闸（非 json
语言如 ```yaml / 无语言 / 大小写错的 heading / 正文 JSON 坏，**仍须拒收**）。守闸测试经变异验证：
把 `(?i:json)` 放宽成 `[A-Za-z ]*`、或给整条正则加 `re.IGNORECASE`，对应守闸立刻变红。

**这一课贵方**自己已经上过**——commit「导航与日志的回读校验改为语义比对——逐字节在 docx 往返下
必然误报」（`788368c`）就是这个结论。同一结论当时只落到了导航与日志的回读校验上，没落到
`_parse_control`。建议贵方检一遍：**凡是会被 docx 往返触及的字节比对，都该改成语义/容忍比对。**
