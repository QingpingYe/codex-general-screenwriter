# 通用编剧创作插件：领域模型与兼容迁移设计

**状态：** 阶段 0 设计草案
**日期：** 2026-10-09
**关联大纲：** `docs/superpowers/plans/2026-10-09-general-screenwriter-upgrade-outline.md`

## 1. 目标与范围

本设计定义把现有绘本编剧插件演进为通用编剧创作工作台所需的基础领域模型、兼容边界和迁移规则。首批支持绘本、电影、短剧和长篇连续剧；题材与风格作为独立标签参与规则匹配。

本阶段只确定概念、契约和迁移边界，不实现具体类型包、用户技能管理界面或新的剧本质量指标。后续实现计划必须以本设计中的标识、层级和兼容规则为前提。

## 2. 当前系统盘点

### 2.1 已具备的通用能力

- 编辑式入口、简报门、知识加载、创作、质检、确认和持久化流程。
- `stage_dag.py` 提供运行清单、阶段状态、依赖排序、条件阶段和 revision run。
- `stage_dag_codex.py` 提供主编独占确认门、多 Agent 派发和顺序降级。
- `knowledge-loader` 提供远端权威知识读取、revision 校验、证据包和 `built_against`。
- `slot_resolver.py` 已保留 `series_id` 与 `project_id` 输入，为作用域技能扩展预留入口。
- 默认只对话、不落盘，用户批准确认门或明确导出后才写文件。

### 2.2 当前的绘本耦合

- 插件入口、入口 skill、manifest 和运行阶段均使用绘本命名。
- `artifact_types` 主要是绘本定位、主题、世界观、角色、大纲和逐页脚本。
- `text-craft` 和 `craft-benchmark-check` 包含逐页字符量、副歌、无字页、拟声词和翻页钩子等绘本指标。
- `stage_dag.py` 的阶段负责人、阶段 ID、确认后持久化策略和插画子图使用绘本固定策略。
- 知识页逻辑键目前固定为 `series_id/project_id/page_type` 三段结构。
- `page_codec.py` 的系统元数据为 `schema_version=1`，只接受现有页面类型和三段 key。

### 2.3 兼容结论

现有阶段编排、确认/修订语义、知识证据记录和写入边界可以作为通用内核的基础。绘本文字工艺、绘本质量指标、逐页格式和插画链路应作为绘本类型能力迁移。旧入口、旧 key、旧产物和旧 run manifest 必须继续可读，迁移通过显式适配完成。

## 3. 目标领域模型

### 3.1 创作上下文

每次创作、修订、审查或导出都绑定一个 `CreativeContext`，包含：

- `medium_id`：媒介/规格类型，例如 `picturebook`、`film`、`shortdrama`、`tv_longform`。
- `genre_ids`：题材与风格标签，可为多个，例如 `mystery`、`comedy`。
- `series_id`：系列标识，可为空。
- `project_id`：项目标识。
- `season_id`、`episode_id`、`scene_id`：长篇项目或细粒度创作单元标识，可为空。
- `delivery_form`：交付形式，例如 `screenplay`、`shooting_script`、`page_script`，由类型包声明。

`medium_id` 与 `series_id` 是两个独立维度。同一系列可以拥有绘本项目、电影项目和短剧项目；项目通过自己的 `medium_id` 选择适用类型包。

### 3.2 作用域

知识和技能使用统一的 `ScopeRef` 表达适用范围：

```text
global
medium
genre
series
project
season / episode / scene
task
```

推荐解析顺序为：

> global → medium → genre → series → project → unit → task

更具体的作用域只在声明允许覆盖时覆盖上层内容。不同作用域的来源、版本、优先级和最终生效结果都要记录，不能通过隐式文本拼接判断最终规则。

### 3.3 作品层级

领域模型包含以下逻辑层级：

```text
Series
└── Project
    ├── Season
    │   └── Episode
    │       └── Scene
    └── Artifact revisions
```

绘本和电影可以只使用 `Project` 与 `Artifact`；短剧至少需要 `Project`、`Episode` 和 `Scene`；长篇连续剧完整使用系列、季、集和场层级。

### 3.4 产物

产物统一包含 `artifact_type`、`medium_id`、`project_id`、版本、状态、来源依赖和父产物引用。产物分为三类：

1. **通用创作产物**：定位、前提、世界观、角色、大纲、结构和正文。
2. **类型产物**：绘本逐页脚本、电影 treatment、短剧集纲、长篇 season arc 等。
3. **生产与评估产物**：场次表、分镜、质量报告、连续性报告、导出文件和资产登记。

现有 `positioning`、`topic_plan`、`worldview`、`characters`、`outline`、`script` 保留为兼容别名。新类型包可以提供更精确的类型产物，但不能改变旧产物的读取含义。

## 4. 通用内核边界

通用内核负责：

- 识别意图、创建 `CreativeContext` 和创作简报。
- 解析类型包、知识和技能，生成运行时解析快照。
- 执行通用阶段 DAG、状态迁移、确认门和修订轮次。
- 维护产物版本、依赖引用、冲突提醒和陈旧检测。
- 执行统一写入策略和用户确认策略。

通用内核不负责具体媒介的句长、页数、场次密度、集长或镜头规则。这些规则由类型包和类型知识提供。

## 5. 类型包边界

类型包是可注册的能力单元，每个包至少声明：

- `medium_id` 和支持的 `delivery_form`。
- 允许的 artifact schema。
- 类型创作阶段及阶段依赖。
- 类型方法论、基准指标和质量规则引用。
- 类型专属导出器和可选能力模块。
- 与旧绘本入口或旧产物的兼容别名（仅绘本包需要）。

绘本包承接现有 `text-craft`、`craft-benchmark-check`、`staging-planner`、插画提示词和图片导出能力。电影、短剧和长篇连续剧在后续专项中分别定义自己的产物和检查规则。

## 6. 知识库模型与兼容策略

### 6.1 知识类别

知识页分为：

- 通用创作规范和方法论。
- 类型规范、格式规范和类型质量标准。
- 题材与风格参考。
- 系列圣经、角色、世界观和时间线。
- 项目事实、制作约束、修订记录和项目评价。

### 6.2 逻辑键迁移

现有三段逻辑键 `series_id/project_id/page_type` 保持可读。新作用域信息不直接拼接到旧 key 中，而通过知识页 schema v2 的显式字段表达：

- `scope_type`
- `scope_id`
- `medium_id`
- `genre_ids`
- `page_type`
- `supersedes` 或覆盖关系

旧页面继续由 schema v1 解析；新页面使用 v2 解析器。旧页面迁移完成前，loader 返回其兼容状态，不把旧页面误报为已经迁移的新权威快照。

### 6.3 证据依赖

`built_against` 在保留现有字段的基础上，增加：

- 命中的作用域。
- `medium_id` 和适用题材。
- 生效优先级。
- 知识 schema 版本。

后续产物的陈旧判断同时考虑页面 revision、作用域链变化、类型包版本和技能版本。

## 7. 技能注册模型

用户技能独立于知识页保存。技能的最小声明包括：

- `skill_id`、版本、作者和状态。
- 适用的 `medium_id`、`genre_ids`、`series_id`、`project_id` 和阶段槽位。
- 输入、输出、依赖和冲突。
- 优先级、覆盖范围和兼容的类型包版本。

技能解析结果加入运行时快照，并与知识证据一起写入产物依赖记录。项目技能只能在其声明的项目作用域内生效，冲突时必须产生可见审计结果。

## 8. 运行记录与工作流兼容

现有 `pb-stage-run-v2` 和 `pb-stage-task-v1` 继续作为旧绘本运行记录格式读取。通用运行记录增加独立的 `context` 和 `resolution_snapshot` 概念，至少包含：

- 创作上下文。
- 类型包标识和版本。
- 生效知识引用。
- 生效技能引用。
- 工作流策略标识。

通用阶段 ID、负责人和确认门策略需要注册化。现有 `pb-*` 阶段 ID 保留为绘本兼容别名；新类型使用与媒介无关的阶段命名。确认结果仍限定为 `approved`、`revision_requested` 和 `cancelled`，修订仍创建新的 run 并重新经过质量检查。

## 9. 兼容矩阵

| 现有对象 | 迁移策略 | 目标状态 |
| --- | --- | --- |
| `picturebook-screenwriter` 入口 | 保留现有入口和别名 | 通用入口可并行接入 |
| `artifact_types` 六类产物 | 保留读取语义，增加类型产物 | 通用产物 + 类型产物 |
| `pb-stage-run-v2` | 旧格式只读兼容，新增 context 适配 | 通用运行记录 |
| `series_id/project_id/page_type` key | 保留三段 key，新增 schema v2 作用域字段 | 作用域知识 key |
| `text-craft` | 迁移为绘本类型方法论 | 类型包技能 |
| 绘本 benchmark | 保留在绘本包 | 类型质量插件 |
| 插画阶段与导出 | 保留为可选绘本能力模块 | 可选媒介能力 |
| `built_against` | 保留旧字段，追加解析快照字段 | 跨版本依赖记录 |

## 10. 阶段 0 交付物与验收

阶段 0 交付以下文档和清单：

1. 本领域模型设计稿。
2. 现有入口、产物、知识页、run manifest 与目标模型的映射表。
3. 旧 key、旧产物和旧运行记录的兼容矩阵。
4. 首批四种媒介的最小类型范围。
5. 后续专项设计的依赖顺序。

阶段 0 通过条件：

- 能解释哪些能力属于通用内核，哪些能力属于类型包。
- 能为任一项目确定 `medium_id`、系列、项目和产物层级。
- 能说明旧绘本项目如何被读取、运行和迁移。
- 能说明知识和技能的生效顺序以及冲突处理入口。
- 未来类型包可以在不修改旧绘本产物读取语义的前提下注册。

## 11. 后续专项设计顺序

阶段 0 通过后，按以下顺序继续：

1. 类型能力包与产物契约设计。
2. 知识库 schema v2、作用域和继承设计。
3. 用户技能注册、解析和治理设计。
4. 通用创作 DAG 与类型工作流策略设计。
5. 绘本类型包迁移设计。
6. 电影、短剧和长篇连续剧类型包设计。
7. 质量评测、迁移工具和输出生态设计。

本设计稿完成后需要先经过用户评审。用户确认后再编写对应的实施计划；确认前不进入类型包或运行内核的代码改造。
