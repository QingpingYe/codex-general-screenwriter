# 通用编剧创作插件升级计划大纲

**状态：** 规划草案
**日期：** 2026-10-09
**目标：** 将现有绘本内容创作插件升级为支持绘本、短剧和长篇连续剧的通用编剧创作工作台。

## 一、升级目标

- 建立统一的编剧创作内核，覆盖需求、开发、写作、修订、质检和输出。
- 通过类型能力包承载不同媒介的结构、格式、方法论和质量标准。
- 支持全局、类型、系列、项目及更细粒度上下文的知识与规则继承。
- 允许用户添加指定类型、系列或项目的专属创作技能。
- 保留现有绘本项目、知识和工作流的可用性，并提供迁移路径。

## 二、设计原则

1. **通用内核与类型差异分离**：阶段编排、确认门、版本和权限属于内核；逐页脚本、场次格式、长篇连续性等属于类型能力包。
2. **媒介类型与题材标签分离**：媒介类型决定结构和输出格式，题材与风格作为可叠加约束。
3. **知识与技能分工明确**：知识库保存规范、方法论、案例和项目事实；技能负责执行步骤、提示模板和检查流程。
4. **作用域可解释**：明确每条规则和技能的来源、优先级、版本和覆盖关系。
5. **兼容优先、分阶段迁移**：先迁移绘本作为兼容类型包，再扩展其他类型。
6. **质量检查随类型交付**：新增一种类型时，同时交付其知识、产物格式、质量规则和代表性评测样例。

## 三、目标架构

### 1. 通用创作内核

负责统一处理：

- 意图识别与创作简报
- 世界观、人物、结构、场次和正文产物
- 阶段 DAG、运行状态、确认门和修订轮次
- 知识依赖、版本记录、陈旧检测和冲突提醒
- 质量门、用户确认和持久化策略

### 2. 类型能力包

每个类型包声明：

- 适用的媒介类型和题材组合
- 创作阶段与结构模板
- 产物类型及格式约束
- 类型专属方法论和质量检查
- 类型专属输出与导出方式

首批类型包：绘本、短剧、长篇连续剧。

### 3. 上下文模型

建议保留以下层级：

> 全局 → 媒介类型 → 题材/风格 → 系列 → 项目 → 季/集/场 → 当前任务

项目继承上层设定，并可在明确规则下覆盖上层配置。系列层用于保存长期世界观、人物弧线、时间线、风格和禁用项。

### 4. 技能注册中心

用户技能独立于知识页管理，至少包含：

- 技能标识、版本、来源和状态
- 适用类型、题材、系列、项目和阶段
- 输入、输出、依赖和冲突声明
- 优先级、覆盖规则和兼容性信息
- 审核、发布、停用、回滚和变更记录

### 5. 知识库适配层

统一处理：

- 类型规范、通用方法论和评价标准
- 系列圣经、角色资料、世界观和时间线
- 项目事实、创作约束和历史修订
- 来源、revision、索引状态和 built-against 依赖

## 四、核心工作流

统一主链路为：

> 需求简报 → 研究/定位 → 世界与人物 → 故事结构 → 分集/场次 → 正文 → 修订 → 质检 → 用户确认 → 输出

不同类型通过类型包决定具体阶段、产物和检查项。工作流需要支持阶段复用、回退、分支、版本对比和修订轮次。

## 五、类型能力建设方向

### 绘本

- 迁移现有绘本文字工艺、逐页脚本、分镜和插画相关能力。
- 将字符量、副歌、无字页、拟声词和翻页钩子等指标限定在绘本包内。

### 短剧

- 支持短集数、强钩子、快节奏和单集闭环结构。
- 建立集级时长、场次密度、冲突推进和结尾悬念检查。

### 长篇连续剧

- 支持系列、季、集、场多层级管理。
- 建立角色状态、时间线、伏笔、回收和跨集连续性台账。
- 支持系列设定继承、项目覆盖和变更影响追踪。

## 六、分阶段迭代路线

### 阶段 0：盘点、建模与迁移设计

- 梳理现有绘本流程中的通用能力和绘本专属能力。
- 确定媒介类型、题材、系列、项目、产物和阶段的统一术语。
- 建立类型矩阵、兼容矩阵和旧数据迁移清单。
- 确定首批类型和每种类型的最小可用范围。

**阶段验收：** 目标架构、领域模型、迁移方案和类型范围获得确认。

### 阶段 1：通用内核与契约

- 抽取通用入口、阶段编排、确认门、修订机制和版本依赖。
- 建立类型包、产物、知识和技能的注册契约。
- 扩展作用域模型和技能解析规则。
- 保留绘本旧入口和旧产物的兼容别名。

**阶段验收：** 能注册一个类型、加载对应规则、运行通用创作流程并完成确认与修订。

### 阶段 2：绘本迁移

- 将现有绘本能力迁移为绘本类型包。
- 将绘本文字指标、插画路径和逐页格式从通用内核中移出。
- 对绘本旧项目做兼容回归，建立绘本端到端样例。

**阶段验收：** 绘本能力保持可用，并能完成从简报到目标产物的完整流程。

### 阶段 3：短剧与长篇连续剧

- 增加短剧的集级结构和节奏规则。
- 增加长篇连续剧的系列、季、集、场模型。
- 建立连续性台账、角色状态和伏笔管理。
- 验证跨集修订和跨项目继承。

**阶段验收：** 三类主要媒介可以使用统一入口，并按各自类型规则生成和检查产物。

### 阶段 4：用户技能中心与治理

- 开放用户创建、导入和管理技能。
- 实现按类型、系列、项目和阶段的技能匹配。
- 增加优先级、冲突审计、审核发布、停用和回滚。
- 将技能版本锁定到产物依赖记录中。

**阶段验收：** 用户技能可以在指定范围生效，来源和覆盖关系可追踪，冲突不会静默覆盖系统规则。

### 阶段 5：质量、迁移与输出生态

- 建立通用质量检查和各类型质量基准。
- 建立代表性样稿、回归评测和跨类型测试集。
- 完成旧项目、旧知识和旧产物的迁移工具与文档。
- 增加短剧集稿、长篇剧本、分镜、制作清单和其他格式的输出接口。

**阶段验收：** 形成可发布的通用编剧插件，具备迁移、验证、审计和持续扩展能力。

## 七、贯穿各阶段的质量与治理要求

- 默认只在对话中生成，文件写入和导出继续遵循用户确认规则。
- 类型权威规则、项目事实和用户实验性技能分开管理。
- 每次创作记录所使用的知识版本、技能版本和类型包版本。
- 项目级硬约束失败时阻断确认；工艺指标偏差需要明确呈现。
- 新增类型必须同时提供最小知识集、产物格式、质量规则和回归样例。
- 所有旧格式和旧依赖记录都需要可读取，并明确其迁移状态。

## 八、后续拆分顺序

后续实施时按以下设计文档拆分：

1. 通用领域模型与兼容迁移设计
2. 类型能力包与产物契约设计
3. 知识库作用域与继承设计
4. 用户技能注册、解析与治理设计
5. 通用创作 DAG 与质量门设计
6. 绘本迁移方案
7. 短剧和长篇连续剧类型包方案
8. 质量评测、输出和发布方案
